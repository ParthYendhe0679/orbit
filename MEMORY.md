# Orbit Trading AI — Context Ledger & Architecture Log

## Tech Stack
- **Backend**: FastAPI, WebSockets, Python 3.13, SQLite / Neon PostgreSQL
- **Frontend**: Vanilla JavaScript (ES6+), Three.js (WebGL 3D Scene), Lightweight Charts / TradingView Widget, CSS3 (Modern Glassmorphism & Monochrome Dark Theme)

Right side: dynamic 3D isometric laptop with live financial candlestick screen, 3D BUY/SELL capsule keys, ascending green area profit chart, soaring pink arrow, gold coin, magnifying glass, and surrounding flock of moving 3D candlesticks.

- **Rules**: Zero silent deletions of existing functionality or agents. Strict minimalism.

- Lesson 46: ORBIT Selective Go Integration (Phase 11): Introduced exactly ONE Go microservice (`orbit-stream`) at `go-stream/main.go` as a high-concurrency WebSocket tick broadcast hub. Architectural justification: Python's `asyncio.Queue`-per-socket `ConnectionManager` adds 0.3–1ms fanout latency per socket — multiplied by N concurrent users. Go goroutines reduce this to <0.05ms. The Python FastAPI backend retains 100% of all analytical logic (Phases 2–10). Go is ONLY used for tick broadcast fanout. Integration: Python calls `publish_tick(payload)` which does a fire-and-forget `urllib.request.urlopen` POST to `http://localhost:8001/publish` inside `asyncio.to_thread` with 50ms timeout. The Go hub fans out to all browser WebSocket connections at `:8001/ws`. Python's `manager.send_json` is kept as a fallback — system works without Go running. Non-tick messages (wallet, positions, signals, logs) remain on Python WebSocket at `:8000/ws`. Lesson: Do NOT require admin rights for Go install — use MSI download via `Invoke-WebRequest` or ensure admin shell for Chocolatey. Constraint: `publish_tick` uses stdlib `urllib.request` only (no httpx dependency added). `STREAM_HUB_URL = "http://localhost:8001/publish"` is a module-level constant for easy override.
